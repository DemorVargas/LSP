# MiniLSP — Реализация Language Server Protocol на Python

LSP-сервер для Python с нуля, без единой сторонней зависимости. Парсит код через модуль `ast`, выдаёт автодополнение/hover/определение/символы через stdio, и включает статический анализ — вывод типов и оценку цикломатической сложности.

## Быстрый старт

```bash
python3 -m src.main
```

Сервер общается по протоколу LSP через stdio. Подаёте JSON-RPC сообщения на вход — получаете ответы.

## Возможности

### Стандартные функции LSP

| Функция | Метод | Описание |
|---------|-------|----------|
| Hover | `textDocument/hover` | Показывает сигнатуру функции, определение класса или тип переменной + docstring |
| Переход к определению | `textDocument/definition` | Определяет символ через AST к его строке определения |
| Автодополнение | `textDocument/completion` | Имена из области видимости + встроенные функции Python + ключевые слова, с дедупликацией |
| Символы документа | `textDocument/documentSymbol` | Верхнеуровневые символы с вложенными детьми (класс → методы) |
| Подпись функции | `textDocument/signatureHelp` | Информация о параметрах при курсоре внутри вызова функции |
| Диагностика | `textDocument/publishDiagnostics` | Ошибки синтаксиса AST (ERROR) + висящие скобка/запятая (WARNING) |

### Пользовательские функции анализа

| Функция | Метод | Описание |
|---------|-------|----------|
| Вывод типов | `textDocument/typeInference` | Выводит типы из аннотаций, литералов, слияния веток, переменных цикла |
| Анализ сложности | `textDocument/complexityAnalysis` | Цикломатическая сложность каждой функции с оценкой риска (low/medium/high/critical) |

### Поддерживаемый синтаксис Python

- Функции (синхронные/асинхронные), классы, методы, вложенные функции
- Аннотации типов (включая синтаксис `int | None`)
- Декораторы (`@property`, `@staticmethod`, `@classmethod`)
- Оператор морж (`:=`)
- Конструкции match/case
- Генераторные выражения (list/dict/set)
- Стили импорта: `import x`, `from x import y`, `from x import y as z`, `from x import *`, относительные импорты
- Docstring-и

## Конфигурация

### Переменные окружения

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `MINILSP_LOG_LEVEL` | `info` | Уровень логирования: `debug`, `info`, `warning`, `error`, `critical` |
| `MINILSP_LOG_FORMAT` | `json` | Формат вывода логов |
| `MINILSP_LOG_OUTPUT` | `stderr` | Куда выводить логи |
| `MINILSP_CACHE_SIZE` | `128` | Ёмкость LRU-кэша для результатов AST |
| `MINILSP_MAX_CONCURRENT` | `4` | Максимум одновременных операций |

### Конфигурационный файл

Создайте `config.json`:

```json
{
  "logging": {
    "level": "debug",
    "format": "json",
    "output": "stderr"
  },
  "performance": {
    "cache_size": 256,
    "max_concurrent": 8
  }
}
```

```json

  "id": 2,
  "method": "textDocument/hover",
```

## Проектные решения

**AST вместо regex:** Весь анализ кода идёт через модуль `ast` Python. Парсинг код регулярками — хрупко и неверно. AST даёт точные номера строк, границы областей видимости и информацию о типах.

**LRU-кэширование:** Парсинг AST — дорогой. Результаты кэшируются на документ с LRU-стратегией, так что часто используемые документы всегда быстрые.

**Инкрементальная синхронизация:** Сервер объявляет `TextDocumentSyncKind.Incremental`, а менеджер документов поддерживает и полные, и частичные изменения — минимум трафика для больших файлов.

**Асинхронный stdio:** Транспорт использует `asyncio.StreamReader` для неблокирующего чтения, так что сервер обрабатывает большие сообщения без блокировки.

**Ноль зависимостей:** Чистый стандартный Python. Без `pygls`, без `pylsp`, без каких-либо сторонних пакетов. Всё написано руками.
